# Phase 04 — Spike: macOS clipboard monitoring, privacy prompts, lazy file paste

## Context Links
- Design §4 flow 5, §5 risks (lazy paste High, macOS privacy prompts Med)
- Gates: [phase-12](phase-12-macos-clipboard-files-history.md)

## Overview
- Priority: P0 | Status: pending | Effort: 1.5-2 wk (C)
- Answer 3 questions: (1) does reading pasteboard trigger privacy alerts on current macOS & how to get persistent allowance; (2) can we put a lazy remote-file entry on the general pasteboard that Finder + top apps resolve on paste; (3) best polling strategy.

## Key Insights
- `changeCount` read is free/no prompt; content reads on recent macOS can trigger "paste from other app" alert (developer preview since 15.4; enforced later). Check `NSPasteboard.accessBehavior` and pattern-detection APIs; user-granted "Always allow" in Privacy settings.
- `NSFilePromiseProvider` is designed for drag-drop; for **pasteboard copy** promises use `NSPasteboardItem` + `NSPasteboardItemDataProvider` with `kPasteboardTypeFileURLPromise`/`com.apple.pasteboard.promised-file-url` — Finder support for paste of promises is the key unknown.
- Self-write marker: add custom type `com.fsync.origin` to items we write → watcher skips (echo loop).

## Requirements
Test matrix (paste a lazily-provided remote file, 200 MiB):
| Target | Lazy expected |
|---|---|
| Finder (Cmd+V into folder) | must |
| Mail / Messages attachment | should |
| Slack, VS Code, Chrome upload field | nice |
Also: concealed/transient (`org.nspasteboard.ConcealedType`, `TransientType`, `AutoGeneratedType`) items from 1Password/Keychain are skipped.

## Architecture
```
spikes/macos-clipboard/ (SwiftUI menubar test app)
  PasteboardWatcher.swift   # Timer 250-500ms, compares changeCount, reads types
  SensitiveFilter.swift     # concealed/transient/autogenerated + bundle-id denylist (frontmost app)
  LazyFileWriter.swift      # NSPasteboardItem + data provider; on request: simulate fetch (sleep + write bytes)
```

## Go / No-Go
| Check | Go | Fallback |
|---|---|---|
| Privacy alert manageable | no alert OR one-time "Always allow" persists across restarts | onboarding screen guiding user to grant; manual mode default |
| Lazy paste in Finder | Finder pastes file, provider called, waits for bytes (≥ 30 s fetch OK) | **Eager fallback**: on remote file clip, download to `~/Library/Caches/fsync/inbox/<item>` (cap 512 MiB total per clip), then write real file URLs |
| Mail/Messages | lazy works | eager fallback for files ≤ cap regardless |
| CPU of polling | < 0.5% CPU at 300 ms | adaptive interval (fast after change, slow idle) |

Hybrid allowed: lazy for Finder-compatible path, eager for small (< 20 MiB) files always (better app compatibility).
