## Unresolved questions
- FFI gap (core owner): history keeps 200-char previews; need a content accessor (e.g. `history_item_reps`) for copy-back; `fetch_rep` works only for items in core's receive log (128 offers).
- No CLI command publishes a files clip, so file-clip receive (eager/lazy) is unit-tested via the `fetch_file_to` closure seam, not end to end.
- Does a global hotkey count as user-originated pasteboard access under macOS privacy enforcement?
- Hotkey Ctrl-Opt-C may clash with other apps (message shown on registration failure).
- History window has no extra auth (phase 12 security note).
- Lazy provider waits on the main run loop; events reach it only when the read arrives via the run loop (AppKit callback), which holds for cross-process readers (spike) but not for a read issued inside a main-queue block of our own app.
