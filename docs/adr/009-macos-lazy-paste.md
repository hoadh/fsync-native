# ADR 009 — macOS clipboard: change detection, privacy, sensitive filter, lazy file paste
Status: accepted for the automated part (macOS 26.6.2 arm64, Xcode 27, 2026-10-14). The Finder/app paste
matrix, real password managers and the privacy alert on a GUI session are still open (see end).

Spike: `spikes/macos-clipboard` (`ClipSpikeCore` library + `ClipSpikeSelfTest` console).
Evidence: `spikes/macos-clipboard/results/selftest-macos26.6-arm64.txt`. Windows counterpart: ADR 010.

## Decision
1. **File clips: hybrid.** Files below `lazyThresholdBytes` (default 20 MiB) are downloaded eagerly
   (`~/Library/Caches/fsync/inbox`, real `public.file-url` items). Larger files use a **lazy
   `NSPasteboardItemDataProvider` on `public.file-url`**: the URL (and the file) comes into existence when
   a reader asks for that type; the provider runs `fetch_file_to`. Total eager cap per clip 512 MiB; above
   it only lazy. `FileClipStrategy` (`lazy | hybrid | eager`) is an app setting; `eager` is the switch
   to use if the manual Finder check fails.
2. **`NSFilePromiseProvider` on the pasteboard: no-go.** A receiver in another process gets
   `NSFilePromiseReceiver`s but the provider is never asked (named and general pasteboard, plain binary
   and app bundle, with `NSApplication.run()`). Promises need a drag session. A reader that only knows file
   URLs sees 0 files.
3. **Provider threading.** AppKit calls the provider on the owner's main thread and the reader blocks.
   Run the download on a background queue and spin the main run loop (`RunLoop.run(mode:before:)`, 50 ms
   steps) inside the provider: a main-thread timer ticked 20 times in a 2 s fetch (1 tick when the main
   thread simply blocks). Failure: leave the type unset; the reader gets no file and returns at once
   (0.28 s), no hang.
4. **Exit policy: clear, never leave a lazy entry.** After the owner exits the types stay listed
   (stale) but no file can be read. On quit, if our lazy clip is still current (changeCount equals the
   value after our write), `clearContents()`. Eager clips need nothing.
5. **Change detection:** poll `NSPasteboard.changeCount` (free, no alert, does not change on reads) and
   read type names only; read content only after the filter says sync. Adaptive: 150 ms for 3 s after a
   change, else 1 s. Idle CPU 0.05% (fixed 300 ms) and 0.02% (adaptive), over 20 s, release build.
   A timer does not see every write: 50 rapid writes gave 1 event with the last value readable (last wins).
6. **Skip rules** (any one skips the change): `com.fsync.origin` (own write),
   `org.nspasteboard.ConcealedType`, `com.agilebits.onepassword`, `org.nspasteboard.TransientType`,
   `org.nspasteboard.AutoGeneratedType`, frontmost bundle id in the denylist (defaults: 1Password 7/8,
   Bitwarden, Keychain Access, Passwords). Only names are logged.
7. **Privacy alert (macOS 15.4+ API):** `NSPasteboard.accessBehavior` is `.default` (= ask on programmatic
   access) until the app first triggers the alert, then `.ask` / `.alwaysAllow` / `.alwaysDeny`, user-set
   in System Settings > Privacy & Security > Paste from Other Apps. Named pasteboards are always
   allowed. User-originated, paste-related access is never alerted. App plan (phase 12 onboarding):
   read `accessBehavior` at launch and after each denied read; if not `.alwaysAllow`, show a step that
   explains the setting and opens the pane; fall back to manual mode (hotkey / menu) until allowed.
   Reading `changeCount`/`types` never needs the permission.

|---|---|

| Lazy paste in Finder | automated reader side GO; Finder itself open. Fallback = eager (setting) |
| Mail/Messages | open; eager <= 20 MiB covers the common case |
| CPU of polling | GO (0.05%) |

## Risks to remember
- Any reader that asks for `public.file-url` data (clipboard managers that snapshot all types) triggers the
  download at copy time, not paste time. The 20 MiB eager threshold and the 512 MiB cap bound this.
- The file URL given to the reader points into the inbox; readers copy it (Finder does). Inbox cleanup runs
  on the retention schedule and never deletes a file of the current clip.
- Frontmost-app denylist is a race (the user may switch apps between copy and poll); type markers are the
  primary signal.
