## Overview
- Priority P3. Estimate 1 d.
- **L2:** each queued send behind a dead peer holds its frame (up to about 256 KiB) for up to 7 s. Replace the queue with one "latest" slot per lane: a new frame overwrites a waiting one, and the running attempt keeps its own. This frees memory during copy bursts and matches latest-wins.
- **L1:** concurrent publishes can interleave per-peer tickets. The apps serialize their publishes. Document it on `publish_clip` ("publishes must be serialized for ordering") and add a debug assertion or log when two publishes overlap. No locking change.
- **L-new-1:** bump `contract_version` to 3 (`Published.pending` appended). macOS and Windows check it at startup, so an old binding against a new library fails with a clear message instead of a uniffi decode error at the first publish.
